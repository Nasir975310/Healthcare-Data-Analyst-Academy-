# Security and data handling

## Reporting
Do not publish security reports containing patient information, credentials, tokens, or private institutional data. Remove sensitive details and contact the repository maintainer through a private channel before public disclosure.

## Data policy
- Use synthetic or properly de-identified data in examples and tests.
- Never commit identifiable patient data, medical records, credentials, API keys, access tokens, or private employer information.
- Do not use educational outputs for diagnosis, treatment, staffing, triage, or other operational clinical decisions.
- Review generated reports and exported files before sharing; local databases and outputs may contain sensitive content.

## Scope
This document is a project handling policy, not a guarantee of regulatory compliance or a formal vulnerability-response service. No security response SLA is currently established.
