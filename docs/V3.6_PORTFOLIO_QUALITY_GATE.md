# v3.6.0 — Portfolio quality gate and reproducibility

## Added
- Interactive 30-item release review across scope/metrics, data governance, reproducibility, technical quality, interpretation and release readiness.
- Critical-blocker declaration that prevents a “ready” decision regardless of checklist completion.
- Local project/reviewer/date/notes tracking, Markdown report export and v3.6-specific JSON backup/import.
- Python repository audit CLI with weighted documentation/evidence checks, bounded secret-pattern checks and basic PHI-shaped-pattern heuristics.
- Healthcare analytics README, data dictionary and metric-definition templates.
- Release checklist and synthetic example repository.

## Run the repository auditor
```bash
python portfolio_quality/scripts/audit_portfolio.py /path/to/project --output portfolio_audit.json
python portfolio_quality/scripts/audit_portfolio.py /path/to/project --strict
```
Strict mode exits 2 when score is below 85 or configured secret/PHI heuristics trigger. The tool is a triage aid and can miss secrets/PHI or report false positives. It does not execute project code, inspect Git history, validate authorisation, certify de-identification or establish regulatory compliance.

## Release gate
A complete checklist is not sufficient if a critical blocker exists. Independent reproduction and manual review are required before public release.

## QA boundary
The Python auditor was executed against the bundled synthetic fixture. Static HTML, JavaScript syntax, JSON and ZIP checks were performed. No browser automation, mobile/cross-browser testing, Windows execution, penetration testing, clinical peer review or independent privacy review was performed.
