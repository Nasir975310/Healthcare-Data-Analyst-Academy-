# Reproducibility and evidence protocol

Evidence must be generated by the system that performed the work. Do not manually edit a status field to PASS.

## Local evidence
Run `python scripts/capture_local_evidence.py`. It executes the module's tests, v5.33 validator and SQLite benchmark, records Python/platform details, and hashes synthetic source/deliverable files.

## PostgreSQL evidence
Run `bash scripts/run_postgres_validation.sh`. The script resets only this module's named Compose volume, initializes a PostgreSQL 16 container from synthetic CSVs, reconciles 91 raw = 90 accepted + 1 exception, and writes `evidence/postgres_validation.json`.

## Power BI evidence
Open the actual PBIX in Power BI Desktop. Complete `evidence/templates/powerbi_validation.template.json`; only change status to PASS after recording PBIX SHA-256, application version, KPI-to-SQL reconciliation, refresh and performance checks. Keep screenshots/exported evidence in the repository.

## GitHub evidence
After pushing, record repository URL, commit SHA and secret/privacy review in `evidence/templates/github_publication.template.json`. Do not put access tokens or private repository credentials in evidence.

## Final gate
Run `python scripts/release_gate.py`. Exit code 2 means external proof remains pending; it is not a project failure, but the project is not fully accepted. Exit code 0 requires all four gates to have evidence marked PASS.
