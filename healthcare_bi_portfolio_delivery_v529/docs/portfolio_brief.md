# Portfolio case study: Synthetic hospital operations and pharmacy utilization

## Business question
Can a small hospital operations team monitor encounter activity, medication utilization and selected observation summaries using a transparent, reproducible reporting workflow?

## Scope and grain
Four CSV source tables: patient (one row per PatientID), encounter (one row per EncounterID), observation (one row per ObservationID), medication (one row per MedicationID). Observations and medication orders are separate child facts. Do not join them directly: that multiplies rows when an encounter has multiple observations and medications.

## Deliverables
Power BI semantic model and M/DAX templates from v5.28; this release adds a deterministic Python build, reconciliation SQL, JSON QA outputs, monthly and medication-class extracts, an executive summary and acceptance checklist.

## Findings (synthetic training data only)
The provided dataset contains six fictional patients, twelve encounters, twenty-four BP observations and sixteen medication orders. The monthly and class-level distributions are generated by the build script; no inference about a real hospital is valid.

## Clinical interpretation boundary
Mean BP values and threshold flags are descriptive demonstrations only. They do not establish hypertension diagnosis, control, treatment quality or guideline adherence. Clinical targets depend on context and authoritative guidance.

## Reproducibility
Run `python src/build_portfolio.py`, then `python -m unittest discover -s tests -v`. The script uses Python standard library only and writes reports under `reports/`.
